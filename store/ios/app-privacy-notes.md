# App プライバシー（ASC）の申告の下書き

コードから書き出したデータの流れ。申告はこれをもとに `asc web privacy` で入れる（skill `store-app-setup`）。

## 端末の外に出るもの

| 何を | いつ | どこへ | 残るか |
|---|---|---|---|
| 投げたメモ・丸太と薪の名前・カジリに作ってほしいもの | 投げる／割り直す／カジリの番 | 中継サーバー（Firebase Functions, asia-northeast1）→ Anthropic Claude API | 中継サーバーは保存しない・ログに中身を書かない。Anthropic での保持は Anthropic のポリシーに従う |
| この先2週間の予定の名前・日時・場所 | 「カジリに見てもらう」を押したとき | 同上 | 同上 |
| その週に片づけた薪の名前と数 | 週のふりかえりを頼んだとき | 同上 | 同上 |
| App Attest の証明 | 中継サーバーを呼ぶとき | Apple / Firebase App Check | 個人を示す情報なし |

広告・アクセス解析・クラッシュレポートは入っていない。アカウントも無い（ユーザー ID を作らない）。

## 申告の案（安全側）

Anthropic が API の入力を一定期間保持する可能性があるので、「収集しない」ではなく次で申告する案。

- **ユーザーコンテンツ > その他のユーザーコンテンツ**: 収集する／**ユーザーに関連付けない**／トラッキングに使わない／目的は **アプリの機能**
- それ以外の項目（連絡先・位置・識別子・使用状況・診断 など）: 収集しない

カレンダーの予定も「その他のユーザーコンテンツ」に含める（押したときだけ送る、とアプリ内とプライバシーポリシーに書いてある）。

Google カレンダーの連携: 予定とメールアドレスは端末と Google の間だけでやりとりし、開発者のサーバーには送らない。カジリに送るのは上と同じ「押したときだけ」なので、申告の項目は増えない。
